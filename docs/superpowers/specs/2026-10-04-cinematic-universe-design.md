# JUWON — A Universe in the Making

작성일: 2026-10-04. 상태: 서면 설계 검토 대기. 이 문서는 구현·설치·배포 완료 보고가 아니다.

## 목적과 범위

주원의 실제 작품을 하나의 세계로 경험하게 하는 공개 포트폴리오를 만든다. 방문자가 스크롤할 때 글자, 카메라, 빛, 실제 프로젝트 화면이 함께 움직이고, 마지막에 KRAUDE·Second Brain 3D·AntiStudy가 드러난다. 효과의 개수보다 장면의 대비와 서사가 중요하다.

사용자가 요청한 실제 Three.js 3D, 타이핑, 영화적인 스크롤 연출, 대표작의 마지막 공개를 포함한다. 사이트 전체의 경험을 바꾸되 개별 프로젝트 프로그램을 재구현하지 않는다. 세계 최초·최고, 모든 기기에서 일정한 프레임률, 영구 무료·무제한을 주장하지 않는다.

현재 공개 기준은 bd40f6efe0a7977c419c3bfe913a37badc054fde이다. 카탈로그 123개 기록, 전시 26개 작품, 24개 작품의 실제 화면 이미지 25장을 보존한다. 사진이 없는 2개 작품은 그대로 미확인 표시하며 가짜 캡처를 만들지 않는다. 공개 화면의 기존 증거·상태·외부 원작 및 협업자 크레딧을 유지한다.

## 선택한 접근

실제 Three.js 장면을 장식 레이어로 쓰고, 읽고 클릭하는 콘텐츠는 HTML로 유지한다. GSAP이 스크롤과 타이포그래피 연출을 조율한다. Lenis는 선택적 데스크톱 스크롤 보간에만 사용한다. 이 방식은 전체 캔버스 UI보다 검색·키보드·접근성을 보존하기 쉽고, CSS만 쓰는 방식과 달리 실제 공간·카메라 이동을 구현한다.

사용자가 GitHub 라이브러리를 요청했지만 모든 라이브러리를 동시에 넣지는 않는다. 조사한 공개 프로젝트에서 필요한 기능만 선택하며, 전체 저장소·과거 기록·예제 에셋을 무작정 복제하지 않는다. 이 단계에서는 아직 패키지를 설치하지 않았다.

## 영화적 흐름

처음 방문은 다섯 장면을 순서대로 지나고, 그 뒤 기존 작품 전시·전체 기록·소개로 이어진다. 네이티브 스크롤 방향을 유지하며 뒤로 스크롤해도 장면 상태가 일관되게 되돌아간다. 이동을 강제하거나 특정 장면을 끝까지 보도록 잠그지 않는다.

1. **탄생 — THE SPARK.** 거의 검은 공간에 작은 빛 하나. “작은 호기심 하나에서…”가 문장 단위로 타이핑된다. “나는 / 만들기 / 시작했다.”는 단어별로 나타난다. 한 번의 조용한 시작 후 카메라가 글자 뒤의 공간으로 들어간다. 주인공은 주원의 이름과 시작하는 행위이며 대표작 이름을 미리 노출하지 않는다.
2. **연결 — THE CONSTELLATION.** 빛들이 궤도와 연결선으로 이어진다. 도구·웹·게임·자동화라는 활동의 범주가 나타나고, 대표작 3개를 제외한 실제 화면들이 서로 다른 깊이에서 떠오른다. 연결은 연출용 상징이며 실제 시스템 통합 완료를 뜻하지 않는다.
3. **여행 — THE WORK.** 공개 카탈로그의 `iphone`, `village`, `yt-korean` 작품 화면을 각각 하나의 장면으로 보여준다. 화면 가까이 이동하는 카메라와 짧은 소개가 맞물린다. 식별자에 해당하는 자료가 없으면 안전하게 생략하고 전시 목록은 유지한다. 텍스처는 실제 캡처이며 프로젝트 서버를 실행하거나 화면을 살아 있는 서비스처럼 위장하지 않는다. 각 장면에 기존 캡처 종류와 설명을 표시한다.
4. **고요 — THE CONVERGENCE.** 화면들이 멀어지고 궤도가 정렬된다. 빠른 타이핑과 강한 빛을 멈춘다. “그리고, 하나의 세계가 되었다.”가 천천히 나타난다. 대비로 다음 장면의 무게를 만든다. 자동 재생 소리와 번쩍이는 스트로브는 없다.
5. **공개 — THE CORE.** `kraude` → `secondbrain3d` → `antistudy` 순서로 큰 제목, 실제 화면, 짧은 설명이 등장한다. KRAUDE는 시설과 세계의 상징, Second Brain은 뉴런 연결, AntiStudy는 미션의 상징으로 각각 다른 공간을 갖는다. 절차적 3D 장식과 실제 프로젝트 캡처를 명확히 구분한다. 세 장면이 마지막에 하나의 궤도로 연결되고 “JUWON — STILL BUILDING.”으로 마무리한다. 개발 중인 항목을 완성 제품으로 승격하지 않는다.

장면의 높이는 데스크톱에서 대략 1.2~2 화면, 모바일에서 1~1.4 화면으로 제한한다. 최종 대표작 구간은 세 개의 짧은 하위 장면으로 구성한다. 고정된 대기 시간은 없고 방문자가 스크롤로 속도를 결정한다. 긴 공백을 만들거나 과도하게 긴 핀 구간을 쓰지 않는다.

상단의 “작품 바로 보기”로 서사를 건너뛸 수 있다. 기존 `#works`, `#selected`, `#projects`, `#about` 링크는 계속 작동한다. 직접 링크·검색 이용자는 마지막 공개를 강제로 기다리지 않는다. 기존 첫 화면의 대표작 노드와 먼저 노출되는 추천 작품은 재배치해 첫 방문의 결말을 미리 보여주지 않는다. `#selected`는 마지막 공개 이후 추천 작품 영역으로 유지한다.

## 시각·타이포그래피

검은색과 웜 화이트를 기본으로 두고 기존 라임을 주원의 서명 색으로 보존한다. 차가운 청록은 연결, 따뜻한 빛은 탄생과 공개에서 제한적으로 쓴다. 깊이는 실제 원근 카메라·광점·얇은 연결선·텍스처 평면으로 표현한다. 흐림과 블룸을 모든 화면에 적용하지 않는다.

타이핑은 시작 문장에만, 단어 등장과 큰 제목 공개는 나머지 장면에 쓴다. 같은 효과를 매 섹션 반복하지 않는다. 한글은 `Intl.Segmenter`의 grapheme 단위로 분리하고, 지원하지 않는 환경에서는 글자를 쪼개지 않고 문장 전체를 페이드한다. 읽을 수 있는 원문 HTML과 시각 장식 레이어를 분리해 화면 읽기 도구가 글자마다 반복해서 읽지 않게 한다. 스크롤 역행 시에도 텍스트 상태는 해당 장면 진행률로 계산한다.

폰트 로딩 실패 시 시스템 한글 폰트로 즉시 표시한다. 애니메이션 준비가 늦거나 실패해도 텍스트는 숨겨진 상태로 남지 않는다. 과장된 사업 성과, 가족 사정, 비공개 채팅, 거짓 사용자 수를 연출용 문구에 넣지 않는다.

## 구성과 데이터 흐름

- `catalog.mjs`: 현재 123개 기록과 증거·캡처의 유일한 원본. 기존 안정된 ID 유지.
- `story.mjs`: 다섯 장면의 문구, 순서, 공개할 프로젝트 ID, 카메라 키프레임. DOM·렌더러와 무관한 장면 진행률 계산 함수를 제공한다.
- `universe.mjs`: 장면 생성, 카메라, 점·선·화면 평면, 텍스처 캐시, 품질별 구성. `init`, `update`, `resize`, `dispose` 인터페이스를 제공한다. 캔버스는 하나다.
- `motion.mjs`: HTML 타이포그래피와 스크롤 진행률을 동기화한다. GSAP/ScrollTrigger와 선택적 Lenis를 연결한다. 시작·중지·재구성 시 리스너와 타임라인을 정리한다.
- `app.mjs` 및 `showcase.mjs`: 기존 검색·필터·상세 모달·전시 설명을 유지하고 장식 모듈을 지연 로드한다. 장식 초기화 실패를 기존 UI 실패로 전파하지 않는다.
- `index.html` 및 `style.css`: 기본 문서 흐름, 건너뛰기, 모션 설정, 정적인 대표작과 전시, 반응형 스타일. 3D는 `aria-hidden`이고 포커스를 받지 않는다.

데이터 흐름은 카탈로그 → 장면 정의 → 정규화된 스크롤 진행률 → 카메라·효과·HTML 표시이다. DOM 콘텐츠가 먼저 준비되고 3D가 나중에 추가된다. 캔버스의 클릭 좌표로 작품 선택을 처리하지 않고 기존 HTML 버튼을 사용한다. 기존 모달의 스크롤 잠금과 `/` 검색 단축키를 보존한다.

렌더러와 스크롤 보간은 하나의 프레임 루프를 공유한다. Lenis 사용 시 GSAP ticker를 이용하고 별도 autoRAF를 켜지 않는다. postprocessing을 켜면 composer만 렌더링하며 같은 프레임을 renderer로 다시 그리지 않는다. 탭 숨김·모션 끄기·종료 시 루프와 효과를 중지한다. 폰트·이미지 로딩과 리사이즈 이후 ScrollTrigger 측정값을 갱신한다. 모달이 열리면 배경 보간을 중지하고 닫으면 네이티브 위치에서 다시 연결한다.

## 라이브러리·배포 방식

조사한 공식 저장소와 각 기능의 역할:

- [Three.js](https://github.com/mrdoob/three.js): 실제 3D 장면·카메라·이미지 평면. MIT.
- [GSAP](https://github.com/greensock/GSAP): 타임라인·ScrollTrigger·SplitText. [무료 표준 라이선스](https://gsap.com/community/standard-license/) 조건을 지키며 MIT로 표기하지 않는다. 이 포트폴리오는 웹사이트 연출이고 경쟁 애니메이션 제작 도구를 만드는 범위가 아니다.
- [Lenis](https://github.com/darkroomengineering/lenis): 선택적 부드러운 스크롤. MIT. 모바일 터치는 기본 네이티브, 모션 감소에서는 비활성화한다.
- [postprocessing](https://github.com/pmndrs/postprocessing): 선택적 블룸·톤 매핑. Zlib. 고품질 단계에서만 사용하며 Three.js peer 호환성을 먼저 검증한다.
- [Anime.js](https://github.com/juliangarnier/anime): MIT 대안. 이번 기본 설계에는 넣지 않는다. GSAP과 겹치는 두 엔진으로 같은 타임라인을 제어하지 않는다.

구현 단계에서 호환 가능한 릴리스 조합을 실제로 시험하고 버전·원본 URL·체크섬·라이선스를 기록한다. 아직 검증하지 않은 버전 조합을 확정값처럼 적지 않는다. 필요한 브라우저 ES 모듈만 사전에 로컬에서 준비해 `public/`의 일반 파일로 보관하며 외부 CDN을 런타임 필수 요소로 만들지 않는다. import map은 로컬 상대 경로를 사용한다. 동적 의존성도 같은 공개 에셋에 포함한다.

검증된 브라우저 모듈은 납품 에셋으로 관리하고, 빌드는 기존 Node 표준 라이브러리 복사 방식으로 유지한다. CI에서 npm 패키지에 의존하는 새 빌드를 추가하지 않는다. 따라서 현재 `SKIP_DEPENDENCY_INSTALL=true` 설정을 몰래 바꿀 필요가 없다. 공개 파일은 현재 빌더가 지원하는 평면 구조를 유지하고 라이선스 고지는 공개 텍스트 파일과 사이트 크레딧 링크로 제공한다. 에셋 테스트의 명시적 허용 목록을 새 파일에 맞춰 갱신한다.

## 성능·접근성·실패 처리

3D는 필수 기능이 아닌 점진적 향상이다. 정적 본문·검색·전시가 먼저 작동해야 한다. 장식 모듈과 장면 텍스처는 지연 로드하며 고품질 화면에도 최초 다운로드에 모든 25장을 넣지 않는다. 이미지 비율을 미리 예약해 레이아웃 이동을 줄인다. GPU 텍스처 캐시는 high 최대 8장, low 최대 4장으로 관리하고 교체 시 자원을 해제한다. 현재 장면과 다음 장면을 우선 보관한다.

품질 단계는 high / low / off이다. high의 DPR은 최대 1.5, low는 최대 1.0으로 제한한다. 초기 점 개수 상한은 high 1,200, low 350이며 블룸은 high에서만 활성화한다. 모바일은 low로 시작한다. 탭이 보이는 상태에서 초기 로딩 2초를 제외한 최근 120프레임 평균 간격이 32ms를 넘으면 high를 low로 낮춘다. low에서도 같은 기준이 2회 연속 발생하면 정적 화면으로 전환한다. 3D 초기화·컨텍스트 복구 실패도 off로 전환한다. 자동 상향 전환은 없으며 재시도는 사용자가 선택한다. 실제 프레임률은 측정으로 확인하며 화면 크기와 브라우저에 따라 다를 수 있다.

첫 화면의 추가 JS는 전송 압축 후 600 KiB 이하를 목표로 측정한다. 초과하면 무조건 전체 라이브러리를 먼저 받지 않고 장면 엔진·후처리를 분리 로드하거나 효과를 줄인다. 단일 공개 파일은 현재 호스팅의 파일 제한 안에 유지한다. 과도한 3D 모델·동영상 배경·오디오 다운로드는 추가하지 않는다.

`prefers-reduced-motion`과 명시적 “모션 끄기”를 지원한다. 모션 끄기는 로컬 브라우저 설정에만 저장하고 서버에 전송하지 않는다. 모션 감소에서는 Lenis·타이핑·카메라 이동을 끄고 전체 문구와 정적 캡처를 즉시 보여준다. WebGL 미지원·비활성화·컨텍스트 손실·모듈 로딩 실패도 같은 정적 경험으로 복구한다. 켜기 재시도는 사용자가 선택할 수 있으나 실패한 자동 초기화를 무한 반복하지 않는다.

키보드 Tab·Enter·Escape, 화면 읽기 도구, 터치, 확대 200%에서 콘텐츠 접근을 유지한다. 장식 캔버스가 버튼을 가리지 않는다. sticky 장면과 전체 페이지 높이가 모바일 브라우저 주소창 변화에도 안정적으로 동작하게 한다. JavaScript가 완전히 꺼져도 HTML 서사·대표작 요약·설명·링크를 읽을 수 있고, 동적 123개 기록 검색은 JavaScript가 필요함을 정직하게 표시한다.

## 검증과 공개 기준

구현 이후 다음 항목을 모두 확인한 뒤 공개한다:

- 기존 123개 기록·26개 전시·25장 캡처가 보존되고, 24개 작품의 캡처 상태 및 미확인 2개가 달라지지 않는다.
- 대표작 순서 `kraude` → `secondbrain3d` → `antistudy`와 뒤로 스크롤 상태가 일치한다. 장식적인 연결을 시스템 통합 증거로 설명하지 않는다.
- 기본 검색·카테고리·전시 필터·상세 모달·키보드·기존 앵커가 동작한다. 대표작 버튼도 기존 상세 정보를 연다.
- 진행률 계산·장면 경계·역방향·한글 분할·모션 상태·실패 폴백을 자동 테스트한다. 타임라인이 없어도 정보가 읽힌다.
- 360px 모바일·데스크톱·200% 확대·모션 감소·WebGL 없음·컨텍스트 손실에서 겹침, 숨겨진 본문, 막힌 스크롤이 없다.
- 실제 화면 검토에서 장면 대비, 글자 속도, 3D 깊이, 마지막 공개를 확인한다. 성능 측정 결과에 따라 품질을 낮추며 시각적 선호를 테스트 통과로 대신하지 않는다.
- 공개 파일 허용 목록·상대 URL·라이선스·버전 기록을 검증한다. 비공개 채팅·다운로드·로컬 경로·인증 정보가 빌드에 포함되지 않는다.
- `npm test`와 `npm run build`가 통과하고 Cloudflare 루트와 GitHub Pages 저장소 접두 경로 모두에서 에셋이 로드된다.

검증용 서버는 사용 중인 localhost 포트를 덮어쓰지 않는 새 포트에서만 연다. 기존 12345 서버 등 다른 프로젝트 프로세스를 중지하지 않는다. 테스트한 변경만 커밋·배포하고 Cloudflare Pages·기존 Workers·GitHub Pages의 해당 배포와 실제 공개 화면을 확인한다. 실패 시 과거 검증 버전으로 되돌리는 새 커밋을 만들며 사용자 작업을 삭제하는 Git reset을 하지 않는다.

## 제외와 다음 단계

유료 API·도메인 구매·계정 권한 확대·DB·런타임 서버·자동 콘텐츠 게시·새로운 AI 모델·개별 프로젝트 기능 구현은 제외한다. 현재 공개 사이트는 이 설계 단계에서 바꾸지 않는다.

서면 설계 승인 후 구현 계획을 작성한다. 구현 계획과 실행 방법까지 검토된 다음 코드·의존성·배포 작업을 시작한다. 승인 전에는 설계 문서만 변경한다.
